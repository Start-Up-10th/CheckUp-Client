# 봉사·알림

### REQ-COM-001 — 봉사 관리 명단

봉사는 기숙사에서 잘못했을 때 받는 벌칙이다. 사감·기숙사 자치위원(관리자)이 봉사자 명단 편집 화면에서 학생의 봉사 횟수를 관리한다(하네스 DEC-021).
명단은 서비스에 저장된 전체 학생이다. 명단에 학생을 따로 추가·제외하는 단계와 제외 확인 다이얼로그는 없다. 학생은 관리 API를 사용할 수 없다.
화면은 `봉사자 명단 편집`(Figma 07)이다. 층 탭(3·4·5층)과 검색창(placeholder `이름, 학번 또는 호실로 검색`)이 있고, 같은 호실끼리 `412호 3명`처럼 묶어 호실 → 이름 → 학번 순으로 보여 준다.
각 행은 이름·학번·`최근 활동 MM/DD`·횟수(글자만)와 `봉사자 지정`(지정됨이면 `지정됨`) 버튼이다. 오늘 지정된 행은 라임 테두리·배경으로 강조한다. 횟수를 바꾸는 `−`/`+`는 이 화면에 없고 학생 관리(DEC-033)에서만 한다.
행을 누르면 학생 상세 다이얼로그가 열려 `남은 봉사 횟수`와 `봉사 이력`(날짜·활동명·±횟수)을 보여 주고 닫기만 있다. 화면 아래의 `당일 지정 N명 · 봉사자 관리 →` 바는 처음 들어오면 보이지 않고, 이 화면에서 `봉사자 지정`을 한 뒤에 나타난다. 지정할 때마다 N이 늘고, 봉사자 관리에 다녀와 다시 들어오면 지정하기 전까지 다시 숨는다(노션 기능명세서 `하단 바 · 봉사자 관리 이동`, DEC-034). N은 봉사자 관리(REQ-COM-006)가 보여 주는 사람과 같게 완료한 학생을 뺀 아직 완료하지 않은 지정 인원이다(패드·핸드폰의 `전교생 N명 · 당일 지정 N명` 줄도 같다). 패드·핸드폰은 바가 목록 패널 아래에 따로 놓이고 바가 없어도 그 자리를 비워 패널 높이가 같으며, 컴퓨터는 패널 위에 겹쳐 가운데에 뜬다(Figma 07).
검색어 하나로 호실·학번·이름을 찾는다. 숫자는 호실 번호나 학번이 정확히 같은 학생만 찾고, 그 밖에는 이름에 포함 → 초성 일치 순으로 앞에 둔다. 검색은 서버가 하는 일이라 규칙의 최종 기준은 서버다.

| 결과 | 문구 |
| --- | --- |
| 검색 결과 없음 | 검색 결과가 없습니다. |
| 명단 조회 실패 | 학생 명단을 불러오지 못했습니다. 다시 시도해 주세요. |
| 봉사 이력 조회 실패 | 봉사 이력을 불러오지 못했습니다. 다시 시도해 주세요. |
| 봉사 이력 없음 | 봉사 이력이 없습니다. |

근거: SRC-VOLUNTEER-PENALTY, SRC-FIGMA-VOLUNTEER. 이전의 명단 추가·제외(SRC-ADMIN-UI, SRC-COMMUNITY, DEC-010)는 이 결정으로 대체됐다.

### REQ-COM-002 — 봉사 횟수 조정

봉사 횟수는 학생이 **앞으로 해야 할 봉사 횟수**다. 학생이 잘못하면 관리자가 `+`로 늘린다(하네스 DEC-020).
봉사를 마친 것은 당일 봉사 완료(REQ-COM-006)로 1 줄이고, 사감이 특별한 사정으로 감면할 때는 `−`로 줄인다(하네스 DEC-021).
횟수 조정은 학생 관리(Figma 08) 학생 상세 다이얼로그에서 `−`/`+`로 정하고 사유를 적어 저장한다(DEC-033). 이전의 봉사자 명단 편집 행별 `−`/`+` 즉시 가감은 Figma에서 빠졌다(DEC-034). 횟수가 0이면 `−`는 비활성화하며 0 미만이 되지 않게 서버도 검증한다.
각 조정 날짜를 기록하고 활동명은 기록하지 않는다. 최근 활동에는 날짜(`MM/DD`)만 표시하고 없으면 `-`다.
통신 재시도는 같은 조정을 중복 반영하지 않지만 사용자가 새로 누른 별도 클릭은 한 번 더 반영한다.
`+`와 `−`는 같은 문구를 쓴다(Figma 07 state messages). 전체 평균·총계 통계와 학생 이름 클릭 상세는 추가하지 않는다. 횟수 조정은 알림을 만들지 않는다.

| 결과 | 문구 |
| --- | --- |
| 횟수 변경 성공 | 봉사 횟수를 변경했습니다. |
| 횟수 변경 실패 | 봉사 횟수 변경에 실패했습니다. 다시 시도해 주세요. |

근거: SRC-NOTION-CHECKUPZIP의 사용자 승인 항목 `봉사 횟수 가감`, 횟수의 의미는 SRC-VOLUNTEER-DUTY·SRC-VOLUNTEER-PENALTY, 화면과 문구는 SRC-FIGMA-VOLUNTEER. 활동명 없음은 SRC-VOLUNTEER-HISTORY.

### REQ-COM-003 — 학생 봉사 조회

학생은 본인의 남은 봉사 횟수와 본인 활동 내역만 확인한다. 다른 학생 조회나 수정은 불가하다.
봉사는 기숙사 벌칙이라 봉사 횟수는 앞으로 해야 할 횟수다(DEC-020·021). 그래서 카드는 Figma 문구 `누적 봉사 횟수` 대신 `남은 봉사 횟수`로 표시하고, `활동 내역`은 자치위원이 완료를 확인한 봉사(완료 한 건이 1회)다. 사감의 `−` 감면은 봉사를 한 것이 아니라 내역에 넣지 않는다(사용자 결정 2026-10-04, SRC-VOLUNTEER-REMAINING).
화면은 남은 봉사 횟수 카드 아래 `활동 내역` 목록이며, 한 줄에 날짜(요일)·횟수를 최신순으로 표시한다(Figma 07 · 봉사 활동). Figma의 활동명은 예시라 표시하지 않는다(REQ-COM-002, 2026-09-26).
인터뷰의 `학생은 자기 봉사 횟수만 확인`은 본인 것만 본다는 뜻으로 보고, 기능명세서·Figma의 활동 내역 목록을 유지한다(사용자 결정 2026-09-26).
로딩은 목록 막대 스켈레톤, 내역이 없으면 남은 횟수 카드는 그대로 두고 목록 자리에 `아직 봉사 활동 기록이 없어요` / `봉사 활동을 하면 여기에 표시됩니다.`, 실패는 `봉사 활동 내역을 불러오지 못했습니다.`와 공통 오류/재시도다.
봉사 횟수와 내역은 일일 출석 초기화 때 지우지 않는다.

근거: SRC-COMMUNITY, SRC-HANDOFF, SRC-USER-UI `봉사 횟수 조회`·`봉사 활동 화면 구성`, SRC-VOLUNTEER-HISTORY.

### REQ-COM-005 — 웹 내부 알림

남기는 유형은 출석 완료, 봉사 활동 등록, 기숙사 공지사항 등록 3개다.
얼굴 재등록 요청과 QR 만료 임박은 명시적으로 삭제됐다. 새로운 알림 유형을 만들지 않는다.
출석 완료 알림은 상태가 실제 성공 처리될 때 생성한다. 중복 인증은 중복 발송하지 않는다.
봉사 알림은 당일 봉사자로 지정될 때 생성한다(하네스 DEC-020). 횟수 조정과 봉사 완료는 알림을 만들지 않고, 지정을 취소하면 그 알림을 지운다.
공지 알림만 선택 동의(`기숙사 공지 알림 수신`)에 연결한다. 서비스 범위는 웹 내부 알림이며 푸시는 포함하지 않는다.
공지 게시판(관리자 공지 작성·수정·삭제, 학생 공지 목록)은 없다(REQ-SCOPE-003). 공지 알림을 누가 어떤 경로로 만드는지는 기능명세서에 정의되지 않았으며 서버 연동 때 담당자가 확인한다.
읽지 않은 알림이 있으면 모바일 홈 헤더 벨과 노트북 사이드바 알림 항목의 벨에 빨간 점을 표시한다. 노트북 사이드바 알림 항목의 배경 강조는 알림 화면에 있을 때만 쓰고 읽지 않음 표시로 쓰지 않는다(사용자 결정 2026-09-25, 팀원이 수정한 Figma 사용자-노트북).
알림 목록에 방문하여 확인하면 미확인 표시를 해제한다. 숫자 배지는 추가하지 않는다.
목록은 뒤로가기·`알림` 제목·최근 알림 영역으로 구성한다. 알림 문구와 상대 시각을 두 줄, 최신순으로 표시한다.
예: 오늘 오전 8:12 / 어제 오후 3:40 / 3일 전. 개인정보를 로그용 메시지로 복제하지 않는다.
빈 상태 `아직 알림이 없어요`, 실패는 공통 오류/재시도다. 클릭 이동 규칙은 필요한 범위에서 담당자가 결정한다.
출석 알림은 출석 데이터 폐기 정책을 따른다. 다른 알림·봉사 보관 기간은 운영 담당 결정 항목이다.

근거: SRC-USER-UI `알림 진입점`, `알림 유형`, `알림 화면 구성`와 이후 삭제 결정, SRC-COMMUNITY. 공지 게시판 제외는 SRC-NO-NOTICE.

### REQ-COM-006 — 당일 봉사자 지정·완료

사감(관리자)은 매일 그날 봉사할 학생을 봉사자 명단 편집(Figma 07)의 `봉사자 지정`으로 지정한다. 인원은 고정하지 않고 관리자가 정한다.
지정할 수 있는 학생은 봉사 횟수가 1 이상인 학생이다. 0인 학생을 지정하면 `봉사가 없습니다.`를 표시하고 서버도 거부한다(하네스 DEC-021).
지정 단위는 학생·운영일이다(DEC-006). 같은 학생을 같은 운영일에 두 번 지정하지 않으며, 지정된 학생의 버튼은 `지정됨`이다.
지정되면 그 학생에게 봉사 알림을 만든다. 지정을 취소하면 그 알림을 지운다. 지정·취소는 봉사 횟수를 바꾸지 않는다.
`봉사자 관리`(Figma 06)는 오늘 운영일의 당일 봉사자 목록이다. 헤더는 `MM/DD 당일 봉사자 N명`이고 `+ 명단에서 지정`으로 07에 이동한다. 각 행은 이름·`학번 · 호실`과 `완료`·`봉사 제외` 버튼이다.
`완료`는 그 지정을 완료로 표시하고 봉사 횟수를 1 줄이며 한 번만 반영된다. `봉사 제외`는 지정 취소다. 완료한 지정은 제외할 수 없다. 학생은 지정·완료 API를 사용할 수 없다.
지정과 횟수는 일일 출석 초기화(08:00) 때 지우지 않는다. 하네스는 지정·완료 버튼을 명단 행에 함께 둔다고 적었지만 Figma는 지정(07)과 완료·제외(06)로 나눠 Figma를 따른다.

| 결과 | 문구 |
| --- | --- |
| 지정 성공 | 당일 봉사자로 지정했습니다. |
| 지정 실패 | 당일 봉사자 지정에 실패했습니다. 다시 시도해 주세요. |
| 이미 지정됨 | 이미 당일 봉사자로 지정된 학생입니다. |
| 봉사 없는 학생 지정 | 봉사가 없습니다. |
| 완료 성공 | 봉사를 완료 처리했습니다. |
| 이미 완료됨 | 이미 봉사를 완료했습니다. |
| 제외 성공 | 당일 봉사자에서 제외했습니다. |
| 완료·제외 실패 | 처리에 실패했습니다. 다시 시도해 주세요. |
| 목록 조회 실패 | 당일 봉사자 목록을 불러오지 못했습니다. 다시 시도해 주세요. |
| 목록 비어 있음 | 오늘 지정된 봉사자가 없습니다. 봉사자 명단에서 지정해 주세요. |

근거: SRC-VOLUNTEER-DUTY, SRC-VOLUNTEER-PENALTY, SRC-FIGMA-VOLUNTEER. `봉사가 없습니다.`와 `이미 봉사를 완료했습니다.`는 Figma state messages에 없고 하네스 REQ-COM-006의 문구다.
