# 화면·표시·반응형

### REQ-UI-001 — 관리자 홈 전개도

최신 관리자 홈 이미지가 기준이다. 좌측 서비스 명칭은 `ADMIN / 기숙사 출석 관리`다.
홈 상단에 선택된 층의 `3층 전개도` 같은 제목, 우측에 3·4·5층 탭을 둔다. 층 탭은 컴퓨터에서도 핸드폰처럼 회색 트랙 안의 세그먼트이고 선택 글자는 굵다(DEC-038).
상단 출석/미출석 2개 통계 카드는 선택한 층의 학생 수를 집계한다. 총원 통계 카드는 추가하지 않는다.
호실은 DataGSM 정보로 자동 그룹화하고 방 번호 오름차순으로 배열한다.
서버는 등록한 학생이 있는 호실만 주므로, 층별 호실 번호 목록(3층 301~320, 4층 401~421, 5층 501~518, Figma 전개도 기준)을 웹이 가지고 학생이 아직 등록하지 않은 호실도 항상 보여 준다. 등록한 학생이 없는 호실은 `0/0명`이고 회색 카드이며, 학생이 등록하고 출석하면 서버가 그 학생의 호실 인원을 올려 맞는 호실에 반영된다(DEC-059).
넓은 화면은 제공 이미지의 7열 그리드 느낌을 따르고 좁은 화면에서는 반응형으로 줄인다.
카드 좌상단은 호실, 하단은 `출석 인원 / 해당 호실 배정 인원`이다. 분모를 4명으로 고정하지 않는다. 휴대폰은 Figma 관리자-핸드폰대로 호실 번호만 보이고 인원은 패드·컴퓨터에서 보인다.
전원 출석은 라임 계열, 일부 미출석은 회색 계열로 구분한다.
빈 방은 없다는 사용자 전제에 따라 공실 범례·공실 관리·빈 방용 다이얼로그는 구현하지 않는다.
호실 추가/제거·배치 편집 기능은 없다. 방 카드에서 상세를 연다.

근거: SRC-HOME-IMAGE, SRC-INTERVIEW `빈 방이 없어`, SRC-ADMIN-UI 중 최신 결정과 일치하는 항목.

### REQ-UI-002 — 호실 상세

호실 카드를 누르면 2단계로 열린다: 읽기 전용 상세(방 번호, `배정 N명 · 출석 M명`, 학생 행의 출석/미출석 배지, `닫기`/`수정`)와 `수정`을 눌러 넘어가는 수정 다이얼로그(출석/미출석 선택, `닫기`/`저장`)다(DEC-043).
학생은 이름순이다. 동명이인은 학번으로 안정 정렬하는 구현 기본값을 사용한다.
`1번`, `2번`은 표시 순번이며 침대 번호가 아니다. 호실 정원/침대 DB를 만들지 않는다.
각 행에 이름, 출석/미출석 선택을 표시한다. `4인실` 대신 실제 배정 인원 기준으로 표현한다.
관리자는 편집 가능하고 학생에게 보여주는 해당 정보는 읽기 전용이다.
수동 수정 동작은 REQ-ATT-006을 따른다.

근거: SRC-ROOM-IMAGE, SRC-INTERVIEW.

### REQ-UI-003 — 학생 홈

학생 홈은 본인 호실 카드가 기본이다. 이름·학번과 `기숙사 N층` 제목을 표시한다.
본인 호실 학생 이름과 현재 출석/미출석 상태를 이름순으로 읽기 전용 표시한다.
초기 인터뷰의 학생 전체 층 전개도 대신 최신 학생 화면 명세의 본인 호실 범위를 적용한다.
호실 영역은 Figma 배치 그림을 쓴다: 위 `창문`, 아래 `출입문` 표시 사이에 학생 카드를 2열로 놓는다(사용자 결정 2026-09-25, SRC-FIGMA-USER — 이전의 "목록 방식으로 대체"를 바꾼 것). 카드의 `N번`은 이름순 표시 순번이며 침대 번호가 아니다. 카드 수는 DataGSM 배정 인원이고 빈 침대 자리를 만들지 않는다. 창문·출입문은 방향 표시용 장식이며 실제 호실 도면·침대 배정 데이터를 요구하지 않는다(침대 번호·고정 정원은 계속 제외, REQ-SCOPE-003).
QR 카메라 진입, 홈/마이 이동, 알림 진입점을 제공한다.
본인 미등록이면 얼굴 등록으로 이동한다. 서버 실패: `서버와 연결이 원활하지 않습니다.`

근거: SRC-USER-UI `메인 화면 진입`, `내 호실 현황`, SRC-ROOM-IMAGE, SRC-INTERVIEW.

### REQ-UI-004 — 학생 마이페이지와 내비게이션

이름 아래 `학번 · 기숙사 N층 NNN호`를 표시한다. 봉사 횟수로 이동하는 `봉사 활동` 항목과 로그아웃이 있다.
출석 과거 기록 메뉴는 없다. 프로필 사진은 미설정 상태에서 시작한다.
모바일 홈/마이 2개 하단 탭은 현재 화면을 강조한다.
QR 카메라·봉사·알림 화면은 뒤로가기 + 제목을 표시하며 모바일 하단 탭을 숨긴다.
학생 노트북 화면은 프로필·홈·QR 출석·마이페이지·알림·하단 로그아웃의 좌측 사이드바를 사용한다.
원문 넓은 화면 기준은 1440×900, 사이드바 240px다. 고정 크기로 작은 화면을 깨뜨리지 않는다.
학생 공지 목록 화면과 공지 알림은 없다(REQ-SCOPE-003). 알림 화면에는 출석 완료·봉사 활동 등록 알림만 보인다.

근거: SRC-USER-UI, SRC-NO-NOTICE.

### REQ-UI-005 — 관리자 반응형

기기별로 라우트를 나누지 않고 한 페이지를 반응형으로 처리한다. 컴퓨터는 라벨 있는 좌측 고정 사이드바, 패드는 축소 레일, 휴대폰은 아이콘만 있는 하단 2칸(홈·메뉴)과 메뉴 시트를 사용한다.
경계값은 관리자 ~767px 휴대폰(하단 탭바) · 768~1279px 패드(축소 레일) · 1280px~ 컴퓨터(사이드바 300px)다.
기본 메뉴는 홈 / QR 코드 생성 / 얼굴 인식 생성 / 봉사자 관리 / 학생 관리다. 휴대폰 하단 바는 라벨 없이 아이콘만 있는 홈·메뉴(햄버거) 2칸이고, 메뉴를 열면 시트에 QR 코드 생성 / 얼굴 인식 생성 / 봉사자 관리 / 학생 관리 / 로그아웃(경고색)이 나온다. 홈이 아닌 화면에서는 메뉴 아이콘이 연두색이다. 이전의 하단 5탭(DEC-026)은 폐기한다(Figma 관리자-핸드폰, DEC-033). 메뉴 구성은 세 구간 모두 동일하고 표현 방식만 바뀐다.
원문 사이드바 폭 300px를 기준으로 이미지 비례와 반응형을 조정한다.
로그인·전개도·호실 수정·QR·카메라·봉사 관리/추가를 세 화면 크기에서 제공한다.
LIVE는 카메라 영역에 있다. 카메라·QR 전체화면은 제공하지 않는다(DEC-036).
컴퓨터·패드는 사이드바/레일 하단에 로그아웃을 두고, 휴대폰은 메뉴 시트 맨 아래에 둔다.

근거: SRC-ADMIN-UI, SRC-CAMERA-IMAGES, SRC-HOME-IMAGE. 휴대폰 5번째 로그아웃 탭은 SRC-NOTION-CHECKUPZIP의 사용자 승인, 아이콘 전용 표시는 SRC-FIGMA-ADMIN-PHONE. 공지 제거는 SRC-NO-NOTICE. 반응형 경계값은 사용자가 제공한 "반응형 기준" 문서(2026-09-23).

### REQ-UI-006 — 공통 상태와 문구

목록 로딩은 본문 스켈레톤으로 표시하고 헤더/내비게이션은 유지한다.
빈 목록은 `아직 데이터가 없어요`(봉사자 관리의 `오늘 지정된 봉사자가 없습니다…`·학생 관리의 `검색 결과가 없습니다.`도 같은 빈 상태 화면에 설명으로 보인다, DEC-049), 오류는 `불러오지 못했어요` + 다시 시도,
비로그인은 `로그인이 필요해요` + 로그인하기를 표시한다. 알림 빈 상태는 `아직 알림이 없어요`다.
상태 메시지는 가로 배너, 성공 체크 아이콘, 오류/안내 점 아이콘을 사용한다. 일시 메시지(조회·저장 실패, 로그인 실패, 인식 결과 등)는 화면 안에 박은 배너 대신 모두 토스트로 보이고(관리자·사용자 공통, DEC-048), 목록 안의 빈 상태·오류 화면·다이얼로그 안 안내는 토스트가 아니라 그 자리의 상태 표시다.
일시 표시 시간·카메라 미권한 전용 화면처럼 미정의인 상세는 담당자가 일관된 기본 상태로 처리한다.
토스트는 `react-toastify`로 보인다(Figma 상태 메시지 모양이 아니라 라이브러리 기본 모양, 사용자 결정 2026-10-07, DEC-048). 핸드폰·패드·컴퓨터 모두 화면 위쪽 가운데이고(관리자·사용자 공통), 성공·안내 2초, 오류 4초 뒤 사라지며 시간은 토스트마다 따로 센다. 토스트가 떠 있는 동안 새 토스트가 생기면 대체하지 않고 쌓아서(최대 5개, 가장 새 것이 맨 앞) 마우스를 올리면(터치는 눌러서) 펼쳐 전부 읽을 수 있다. 같은 문구를 다시 띄우면 하나만 남고 시간만 다시 센다. 오류는 `alert`, 성공·안내는 `status` 역할로 알린다.
서버가 요청이 너무 많다고(429) 답하면 `Retry-After`를 읽어 `잠시 후 다시 시도해 주세요.`를 안내(neutral)로 보이고, 헤더가 없으면 1초 뒤 다시 시도한다(관리자·학생 화면, DEC-045).
특정 예외 메시지가 원문에 없다고 예외 검증 자체를 없애지 않는다.

| 상황 | 제공 문구 |
| --- | --- |
| 학생 로그인 실패 | 로그인에 실패했습니다. 다시 시도해 주세요. |
| 로그인 성공 | 로그인되었습니다. |
| 관리자 인증 실패 | 계정 또는 비밀번호가 올바르지 않습니다. |
| 관리자 권한 부족 | 관리자 권한이 없는 계정입니다. |
| 내 정보 조회 실패 | 정보를 불러오지 못했습니다. |
| 전개도 조회 실패 | 전개도를 불러오지 못했습니다. |
| 전개도 수정 실패 | 전개도 변경에 실패했습니다. 다시 시도해 주세요. |
| 학생 검색 결과 없음 | 검색 결과가 없습니다. |
| 학생 명단 조회 실패 | 학생 명단을 불러오지 못했습니다. 다시 시도해 주세요. |
| 봉사 조회 실패 | 봉사 활동 내역을 불러오지 못했습니다. |

얼굴·QR·봉사 변경 문구는 해당 분야 명세에서 관리한다. 문구에 자체 비밀번호가 언급되더라도 자체 로그인 폼을 추가하지 않는다.

근거: SRC-USER-UI, SRC-ADMIN-UI.

### REQ-UI-007 — 설치 가능한 앱 셸(PWA)

PWA는 관리자와 학생이 함께 쓰는 하나다(DEC-055). 시작 경로는 루트(`/`)이고, 앱 첫 화면이 로그인 상태에 따라 관리자 홈(`/admin`)·학생 홈·동의·로그인으로 보낸다. 관리자용 manifest·이름·아이콘은 따로 두지 않는다.
설치 범위는 앱 셸(레이아웃·정적 자산)에 한정한다. 정적 자산(JS/CSS/폰트/아이콘)만 캐시하며,
그 외 모든 요청(페이지 네비게이션, 출석·얼굴 인식·봉사 등 데이터 API 포함)은 캐시를 거치지 않고 항상 네트워크로 보낸다.
네트워크가 없으면 로그인/틀 정도는 뜰 수 있어도 데이터가 필요한 화면은 정상 동작을 보장하지 않는다.
홈 화면 설치는 오프라인 동작을 뜻하지 않는다. 오프라인 얼굴 인식은 범위 밖이다(REQ-SCOPE-003, DEC-041).
앱 이름은 `CheckUp`이다(설치 이름·짧은 이름·iOS 홈 화면 이름·브라우저 탭 제목, DEC-056). 앱 아이콘은 CHECKUP 로고를 밝은 회색 바탕에 크게 놓은 것이다(컴퓨터에 설치할 때 쓰는 일반 아이콘은 가로 96%, 폰에서 쓰는 마스크용과 iOS는 88%, DEC-057).

근거: SRC-PWA-DECISION. DEC-024, DEC-055(DEC-025 대체).
